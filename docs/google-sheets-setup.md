# 結帳系統串接 Google 試算表（Google Apps Script）

流程：網站結帳 → Apps Script 網頁應用程式 → 寫入試算表 → 寄通知信 → 回傳訂單編號。

> 在完成第 5 步之前，網站會維持「示範模式」（不會送出任何資料），所以可以安心先上線。

## 1. 建立試算表
1. 到 Google 試算表建立一份新的空白試算表，命名例如「金煎所訂單」。

## 2. 貼上程式
1. 試算表選單：**擴充功能 → Apps Script**。
2. 刪掉預設的 `function myFunction() {}`，把本專案 [`gas/Code.gs`](../gas/Code.gs) 的全部內容貼上，按 💾 儲存。

## 3. 初始化與觸發條件
1. 上方函式選單選 **`setup`**，按 ▶ 執行。第一次會要求授權（選你的帳號 → 進階 → 前往專案（不安全）→ 允許）。
   - 會自動建立 4 個分頁：**訂單、訂單明細、商品、設定**，並帶入目前菜單與價格。
2. 再選 **`installTriggers`**，按 ▶ 執行，會建立：
   - 店員把「狀態」改成 **可取餐** → 自動寄信通知顧客（需顧客有填 Email）。
   - 每天 21:30 寄出當日訂單摘要給店家。

## 4. 部署成網頁應用程式
1. 右上角 **部署 → 新增部署作業**，類型選 **網頁應用程式**。
2. 設定：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
3. 按部署，複製 **網頁應用程式網址**（結尾是 `/exec`）。

## 5. 把網址放進網站
打開 `index.html`，找到這一行，貼上網址後提交到 `main`：

```js
const ORDER_API = "https://script.google.com/macros/s/xxxxxxxx/exec";
```

也可以把網址貼給 Claude，請它代為修改並推送。

## 6. 測試
1. 先在瀏覽器開啟網頁應用程式網址，看到 `{"ok":true,...}` 代表部署成功。
2. 到網站下一筆測試訂單（Email 填自己的）。
3. 檢查：「訂單」分頁多一列、「訂單明細」多對應列、信箱收到通知與確認信。
4. 在「訂單」分頁把該筆的狀態改成 **可取餐**，確認顧客信箱收到通知。

## 日常操作
| 想做的事 | 怎麼做 |
|---|---|
| 改價格、新增/下架商品 | 改「商品」分頁。價格以這裡為準，前端傳來的價格會被忽略。「上架」填 `FALSE` 即暫停供應 |
| 修改通知信箱 | 「設定」分頁的「通知信箱」（留空＝部署者的 Gmail） |
| 設定宅配運費 | 「設定」分頁的「宅配運費」 |
| 關閉顧客確認信 | 「設定」分頁的「寄送顧客確認信」改 `FALSE` |
| 處理訂單 | 「訂單」分頁的「狀態」下拉選單：新訂單 → 製作中 → 可取餐 → 已完成 / 已取消 |

## 修改程式後要重新部署
改了 `Code.gs` 之後，**部署 → 管理部署作業 → ✏️ 編輯 → 版本選「新版本」→ 部署**。網址不會變，不需要改網站。

## 新增商品時要注意
網站的商品清單寫在 `index.html` 的 `products`，商品 ID 必須和試算表「商品」分頁的 **商品ID** 一致，否則下單會顯示「有商品已下架或不存在」。

## 安全性設計（已內建）
- 金額由伺服器依試算表價格重算，改前端價格沒用。
- 同一份訂單重送（網路不穩時再按一次）不會重複建立。
- 隱藏欄位陷阱、同一支電話 20 秒內只能下一筆、輸入長度與格式驗證。
- 使用者輸入若以 `=`、`+`、`-`、`@` 開頭會加上單引號，避免被當成試算表公式。
- 寫入時加鎖，同時下單不會撞號。

## 限制與提醒
- 網頁應用程式網址是公開的（任何人都能送訂單），所以請搭配「訂單」分頁人工確認，不要在未確認前就備料大量訂單。
- 個人 Gmail 每天最多約 100 封通知信；Google Workspace 較高。
- 目前沒有線上付款。收款方式請由店家與顧客確認。
- 網站的隱私權說明在設定 `ORDER_API` 後會自動改成「資料會儲存在店家 Google 試算表」。若要正式營業，建議另外補上完整的隱私權政策。
